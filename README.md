# ru-text

Правила написания русских текстов для Claude Code — без дословного перевода с английского.

- `rules.md` — ядро правил: принципы и то, что модели реально пишут в наших сессиях. Подключено из `~/.claude/CLAUDE.md`, поэтому действует во всех проектах: ответы, комментарии в коде, описания команд, тексты интерфейсов. Сообщения коммитов в эти правила не входят: они пишутся на английском по отдельному правилу.
- `glossary.md` — справочник оборотов, фраз для писем и терминов. Читается по требованию, когда пишется длинный текст.
- `inbox.md` — поправки от пользователя из всех сессий, «было → стало». В git не входит.
- `bin/ru-text` — команды: `add` записывает поправку, `stats` считает частоту, а `changed` нужна хуку `UserPromptSubmit`.
- `bin/patterns.py` — список счётчиков для `stats`.
- `baseline-2026-11-25.md` — подсчёт по протоколам до появления правил, точка «до».

## Как это работает

- **Новые сессии и подагенты** получают `rules.md` через импорт в `CLAUDE.md`.
- **Хук `UserPromptSubmit`** в `~/.claude/settings.json` следит за изменением `rules.md`. Если файл изменился после того, как сессия прочитала его, модели приходит указание перечитать файл — со следующим сообщением. Новые сессии получают хук при запуске, уже запущенные — после просмотра `/hooks` или перезапуска.
- **Поправки.** Когда пользователь поправляет русскую фразу, модель записывает пару командой из папки правил: `bin/ru-text add "было" "стало" "пояснение"`.
- **Подсчёт.** Раз в месяц стоит смотреть, что и как часто пишут модели. Запускайте команды из папки проекта:

      bin/ru-text stats --since 2026-11-25   # после появления правил
      bin/ru-text stats --until 2026-11-24   # до

  Протоколы хранятся 30 дней, поэтому точку «до» на 25 ноября мы сохранили в `baseline-2026-11-25.md`. Ключ `--examples 3` показывает до трёх примеров на каждый счётчик: многие счётчики ловят и правильные употребления («просто», «при этом»), поэтому верьте числу только после просмотра примеров. С этим ключом вывод содержит тексты из всех ваших проектов — в репозиторий его не сохраняйте.

## Установка на новой машине

Папка может лежать где угодно: правила и скрипт не зависят от её адреса, скрипт вычисляет его по собственному расположению. Нужны `git` и `python3` версии 3.7 или новее; код проверен на 3.9 и 3.13. В примерах ниже вызывается системный `/usr/bin/python3` — если на вашей машине его нет, подставьте свой путь.

Пропишите адрес папки на каждой машине отдельно — в двух местах. В примерах ниже замените `<папка>` на свой путь.

1. Склонировать репозиторий куда удобно:

       git clone git@github.com:code-skald/ru-text.git <папка>

2. Подключить правила: дописать в `~/.claude/CLAUDE.md` строку

       @<папка>/rules.md

3. Подключить хук: в `hooks` → `UserPromptSubmit` файла `~/.claude/settings.json` добавить ещё одну запись рядом с существующими:

       {
         "hooks": [
           {
             "type": "command",
             "command": "/usr/bin/python3 -I <папка>/bin/ru-text changed || true",
             "timeout": 5
           }
         ]
       }

4. Проверить: `/memory` показывает `rules.md` среди загруженных файлов, а `/hooks` — хук на `UserPromptSubmit`.

Шаги 2 и 3 можно поручить Claude Code: откройте сессию в папке `ru-text` и скажите «настрой по README».

## Синхронизация между машинами

- Изменили правила — `git push`. На другой машине — `git pull`: сессии перечитают правила со следующим сообщением.
- `inbox.md` и `.state/` у каждой машины свои, в git они не входят. Поправки разбирают там, где накопились.

## Как пополнять правила

1. Записывать поправки в `inbox.md` командой выше — из любой сессии.
2. Разобрать накопившееся: повторы убрать, общее превратить в правило, перенести в `rules.md`. То, что встречается редко, но задевает — в таблицы ядра; обороты для длинных текстов — в `glossary.md`.
3. Подтверждённую кальку добавить и в `bin/patterns.py` — тогда она попадёт в месячный подсчёт.
4. Закоммитить и отправить в репозиторий (`git push`). Изменение `rules.md` сами сессии подхватят через хук.

В `rules.md` не писать адрес папки — он у каждой машины свой — и не ставить знак `@` перед текстом: файл импортирует сам себя.
